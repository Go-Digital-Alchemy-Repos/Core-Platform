# Shipping quote orchestration (unmounted)

This service connects the accepted test-only quote storage, preparation, authorization, transport and public projection. It does not register a provider, mount a route, start a worker, buy labels, update checkout prices, reserve inventory, create fulfillments or send notifications.

`createShippingQuoteService` requires an explicit database, authorization adapter and transport. `easyPostShippingQuoteAuthorization` uses the accepted uncached generation authorization functions and recognizes only the concrete error class's five claim-denial codes. Unexpected database failures return a sanitized 503. Tests can inject a synthetic transport; there is no fake authorization default.

The unmounted router factory requires supplied admin and ecommerce guards and adds private no-store headers. The integrating parent must supply its real authentication/admin and feature middleware. POST `/orders/:orderId/shipping-quotes` uses the `Idempotency-Key` UUID header and the existing strict versioned request body. GET `/orders/:orderId/shipping-quotes/:attemptId` scopes the attempt to that order. `/shipping/providers/easypost/quote-readiness` returns the strict shared readiness shape. No private snapshot, credential generation, secret, fence, carrier account or provider shipment identity is projected.

POST locks credential authorization, then the order, resolves a same-key replay before current authorization or eligibility, and for a new claim reads the locked location and the order's items/fulfillment rows. Existing fulfillment writers serialize through that order lock. Preparation validates eligibility and snapshots the server addresses, selected items and normalized parcel. The claim and snapshot commit before transport. A short new transaction checks the generation and the still-pending original fence before dispatch. The captured snapshot and approved credential tuple are used for that call: an edit or credential rotation after this final transaction cannot retroactively cancel already-authorized I/O. GET marks changed current inputs/generation stale; it does not reprice or dispatch.

The pending deadline is 30 seconds from claim. The accepted transport has a 15-second abortable request/body deadline. These are JavaScript/application bounds, not an OS hard deadline. Waiting through the claim deadline prevents dispatch; GET and bounded maintenance convert expired pending to unknown without granting another owner. Only the original fence can complete a late response. Same-key POST never retries unknown or pending provider work. New requests with a fresh key are separate operations; quotes are informational and can be stale immediately after any observation.

Definite rejection/no-rates becomes unavailable, ambiguous transport becomes unknown. If recording a provider response fails, a separate transaction first reads the durable outcome (a commit acknowledgement may have been lost) and marks only an unresolved original fence unknown. If that recovery cannot persist/read, the client receives 503 and must retain the same key. No provider retry occurs. This does not claim exactly-once external delivery or prove that a timed-out external request did not reach EasyPost.

Current staleness compares a schema-normalized, code-unit-sorted snapshot hash against the accepted hash. The immutable client parcel is retained while server addresses, location activity, order eligibility and remaining quantities are checked again. A small valid placeholder parcel is used only in local preparation of current server inputs, then replaced by the accepted normalized parcel; it is never sent to the provider. This avoids applying the client's per-unit input cap a second time to converted ounces/inches. Missing/redacted snapshots and elapsed 15-minute freshness are stale. A real database failure is not recast as an unconfigured provider or an ordinary stale observation.

`maintain(batchSize)` accepts 1–500 and processes at most that many expired pending rows and that many terminal snapshots in one transaction. Each selection uses `FOR UPDATE SKIP LOCKED`, and updates are scoped to those selected IDs. Only terminal snapshots at least 30 days old are redacted; pending/unknown snapshots are retained. No unbounded storage sweep is called. There is no scheduled invocation in this slice; the integrating runtime must arrange approved maintenance before enabling quotes.

Validation uses `SHIPPING_QUOTE_SERVICE_TEST_DATABASE_URL`, restricted to a query-free PostgreSQL URL at `127.0.0.1/core_shipping_quote_service_test`. The opt-in suite applies actual migrations, uses real PostgreSQL transactions and synthetic fetch responses, and includes the real credential authorization module for generation approval, concurrent replay and rotation checks. Mounted HTTP tests use only an ephemeral loopback listener and synthetic guard middleware; integrating the real admin mount remains a separate acceptance gate.
